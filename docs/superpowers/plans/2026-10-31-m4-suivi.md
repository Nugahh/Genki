# M4 Suivi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The repository code is the reference where this plan and the code differ.

**Goal:** Voir les courbes : un onglet Suivi avec un hub de cartes (mini-courbe, valeur, variation), des écrans de détail par rubrique (période Jour/Semaine/Année, puces de courbes, graphique avec ligne d'objectif, résumé), une liste de cartes personnalisable et enregistrée dans `users/{uid}.ui`, et les jauges de Aujourd'hui qui ouvrent le détail.

**Architecture:** Nouveau module `src/modules/tracking/{domain,application,adapters,ui}`. Le domaine est pur : périodes et seaux (jour, semaine lundi→dimanche, année par mois), registre de `MetricDefinition`, séries, résumés, variation, couleurs de graphique (spec §9). Un seul port de lecture `FactsSource.observeRange(from, to)` renvoie des `DayFacts` par jour ; deux sources l'alimentent (les documents `days/{date}` ; les séances, via `training`) et le cas d'usage les fusionne. Les préférences d'affichage (`ui`) vivent dans le module `settings` (premier port d'écriture du profil, que M6 complète). Les graphiques sont dessinés avec `react-native-svg`.

**Tech Stack:** Expo Router (onglet Suivi, pile `suivi/index` + `suivi/[section]`), React Native Paper, `react-native-svg` (ajout natif : reconstruire le client de développement), Firestore (RN Firebase, lecture par plage de `documentId`), Jest + RNTL, émulateur Firestore.

## Global Constraints

- Français dans l'interface, code et commentaires en anglais. Métrique, formats fr-FR.
- Spec §6 Suivi : hub = cartes de métriques avec mini-courbe, valeur et variation sur la période, sélecteur Jour/Semaine/Année, bouton « Modifier » (masquer, ajouter, réordonner) ; la liste ordonnée est dans `users/{uid}.ui` (`hubMetrics`, `period`). Détail = sélecteur de période partagé, puces de courbes, graphique avec ligne d'objectif, résumé (moyenne, jours dans la cible, meilleur jour), contenu propre à la rubrique.
- Spec §6 période : Semaine par défaut ; semaine calendaire lundi→dimanche avec flèches vers les semaines précédentes ; Année = année civile, une barre par mois (moyenne journalière du mois) ; Jour = le détail de la journée, comparé à la veille pour les valeurs à une mesure par jour. Une rubrique sans données propose l'action utile.
- Spec §9 couleur des graphiques : jour terminé vert ≥ 90 % de l'objectif, orange 60–89 %, rouge en dessous ; calories : vert 90–105 %, orange 60–89 % ou 106–110 %, rouge sinon. Le jour en cours est en pointillé. Moyennes et décomptes « dans la cible » ne comptent que les jours terminés ; « dans la cible » = ≥ 90 % de l'objectif (calories : 90–105 %).
- Spec §6 « Tout est touchable » : Calories et Protéines ouvrent Suivi › Nutrition (courbe correspondante), Pas ouvre Suivi › Activité, Eau garde son volet d'ajout. `backBehavior="history"` : de Suivi on revient à Aujourd'hui ; retoucher l'onglet Suivi renvoie au hub.
- Spec §4 : `days/{date}` = `waterMl`, `kcal`, `proteinG`, `carbsG`, `fatG` (+ `steps`, `weightKg`, `waistCm` qui arrivent avec M5/M6 : le registre sait déjà les lire).
- Jusqu'à M6, la règle de couleur des calories reste celle de la spec §9 (le mode d'objectif viendra avec les réglages).
- Cibles tactiles 48 dp, libellés d'accessibilité en français qui commencent par le texte visible, messages d'état avec `accessibilityLiveRegion="polite"`, couleurs et polices uniquement par le thème (`src/theme.ts`) ; un graphique a un texte alternatif qui dit la même chose que la courbe.
- Un module n'importe pas les internes d'un autre (`dependency-cruiser`) ; `domain/` est du TypeScript pur, sans import hors de `domain/`.
- Avant de conclure : `npm run lint`, `npm run typecheck`, `npm test`, `npm run lint:deps`, et `npm run test:emulator` (règles et Firestore touchés). Ajout de paquet : `npx expo install`.

## Décisions de M4

1. **Graphiques en SVG** (`react-native-svg`) : barres pour ce qui se cumule par jour (calories, macros, eau, pas, volume), courbe pour les mesures (poids, tour de taille). Une seule bibliothèque, un composant `SeriesChart` et un `MiniCurve`.
2. **Valeur d'un seau** = moyenne des jours terminés qui ont une valeur ; le jour en cours est tracé en pointillé avec sa valeur du moment et n'entre pas dans les résumés. Année : la barre d'un mois est la moyenne journalière du mois.
3. **Rubriques de M4** : nutrition, activité, corps, entraînement, eau. Tabac arrive avec M6 (il ajoute sa rubrique au registre). Une rubrique inconnue renvoie au hub.
4. **Rubriques sans donnée** : activité et corps lisent déjà `steps`, `weightKg`, `waistCm` ; tant que M5/M6 ne les écrivent pas, elles affichent un état vide qui dit quoi faire (le lien vers Réglages › Pas arrive avec M5).
5. **Cartes du hub par défaut** : calories, protéines, eau, pas, poids, volume d'entraînement. « Modifier » : monter, descendre, masquer ; la liste des masquées sert d'« Ajouter une stat ». Pas de glisser-déposer (aucune bibliothèque de gestes ajoutée).
6. **Préférences** : `users/{uid}.ui` écrit par fusion (`merge`), lu en direct ; un identifiant de métrique inconnu est ignoré à la lecture.
7. **Contenu propre à une rubrique** par fente `renderExtras` de l'écran, remplie dans la route (qui a accès à tous les modules) : nutrition = répartition des macros + lien vers le journal du jour (le journal d'un autre jour n'existe pas : `shortcut:` noté) ; eau = verres du jour (vue Jour) avec suppression ; entraînement = séances faites sur prévues et lien vers les paliers.
8. **Calories et Protéines** de Aujourd'hui ouvrent désormais Suivi › Nutrition (spec §6) au lieu du journal ; le journal reste l'onglet Repas et le lien de la rubrique Nutrition.

## Limites connues de M4 (à noter dans le code par `shortcut:`)

- Le détail par repas d'un jour passé n'existe pas : le lien du journal ouvre le jour en cours.
