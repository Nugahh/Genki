# M5 Pas et Health Connect Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The repository code is the reference where this plan and the code differ.

**Goal:** Voir ses pas : la jauge Pas sur Aujourd'hui (rythme, source, heure de la dernière synchro), le bouton Synchroniser, la synchro à l'ouverture et au retour au premier plan, la rubrique Activité du Suivi (courbe, source, synchro) et Réglages › Pas (permission, source Fitbit détectée, sources, raccourci Health Connect, appareil qui envoie les pas).

**Architecture:** Nouveau module `src/modules/steps/{domain,application,adapters,ui}`. Un port `HealthDataSource` (lire le total de pas d'un jour, les sources, la permission, l'état du service) avec un adaptateur Health Connect (`react-native-health-connect`) et un adaptateur en mémoire ; l'API Google Health reste un second adaptateur futur (spec §8). Un port `StepsRepository` écrit `days/{date}` (`steps`, `stepsSource`, `stepsSyncedAt`, par fusion) et le document `devices/{id}` (`stepsWriter`). Un seul téléphone écrit les pas : celui dont `stepsWriter` est vrai.

**Tech Stack:** `react-native-health-connect` (module natif Android + plugin Expo ; ne tourne pas dans Expo Go), `expo-application` (identifiant stable de l'appareil), Firestore, Jest + RNTL, émulateur Firestore.

## Global Constraints

- Français dans l'interface, code et commentaires en anglais. Cibles 48 dp, libellés d'accessibilité qui commencent par le texte visible, `accessibilityLiveRegion="polite"` pour les états, couleurs par le thème.
- Spec §7 : tracker Fitbit → application Fitbit → Health Connect → notre application → `days/{date}.steps` ; lecture au premier plan (à l'ouverture et au bouton), pas d'arrière-plan ; l'agrégat de Health Connect applique la priorité choisie par l'utilisateur ; ne jamais filtrer sur l'ancien nom d'origine `android` (les pas natifs du téléphone ont un nom synthétique depuis juin 2026) ; Android 14 ou plus pour le comptage natif ; le tracker se synchronise toutes les 15 minutes environ : la jauge n'est pas en direct.
- Spec §7 Réglages › Pas : trois lignes d'état (permission de lecture accordée ; source Fitbit détectée avec l'heure de la dernière donnée ; étapes pour activer l'écriture dans l'application Fitbit), « le téléphone compte les pas » si le Fitbit n'est pas détecté ; liste des sources avec l'heure de la dernière donnée ; « Ouvrir Health Connect » (priorité) ; « Ce téléphone envoie les pas » (`devices/{id}.stepsWriter`) ; mode de source Automatique seulement.
- Spec §4 : `days/{date}` = `steps`, `stepsSource`, `stepsSyncedAt` ; `devices/{id}` = `name`, `stepsWriter` (booléen), `lastStepsSyncAt`.
- Spec §9 : la jauge des pas suit la règle du rythme (`paceColor`), objectif 8 000 par défaut (`profile.goals.steps`).
- Spec §7 Bouton Synchroniser : lit le total du jour et met à jour Firestore ; ne force pas le tracker ; propose d'ouvrir l'application Fitbit si Android le permet.
- Un module n'importe pas les internes d'un autre ; `domain/` est du TypeScript pur. Avant de conclure : `npm run lint`, `npm run typecheck`, `npm test`, `npm run lint:deps`, `npm run test:emulator`. Ajout de paquet : `npx expo install`, après lecture de la doc.

## Décisions de M5

1. **Rien de ce module ne se vérifie ici** : l'émulateur n'a pas de Fitbit et Health Connect n'y a pas de données. Les cas d'usage et l'interface sont testés contre un `HealthDataSource` en mémoire ; l'adaptateur Health Connect est mince (une conversion par fonction) et se vérifie sur le téléphone (checklist du README).
2. **Un seul écrivain.** Au premier lancement, un téléphone sans écrivain connu devient l'écrivain (`stepsWriter: true`) ; un second téléphone lit les pas du jour dans Firestore et ne les écrit pas, tant que l'utilisateur ne le désigne pas dans Réglages › Pas. Désigner un téléphone retire le rôle aux autres (un lot d'écriture sur `devices`).
3. **Lecture de deux jours** : la synchro lit hier et aujourd'hui (les pas d'hier arrivent parfois tard, le tracker se synchronise toutes les 15 minutes) ; seul un total qui change est réécrit.
4. **Jour en profil, instants en UTC** : un jour est l'intervalle entre deux minuits du fuseau du profil (`dayBounds`), changements d'heure compris.
5. **Pas de lecture en arrière-plan** (spec §7) : ajout possible plus tard, avec une permission de plus.
6. **Historique** : au premier lancement, la synchro remonte 30 jours (le maximum que Health Connect donne avant la première autorisation), un jour à la fois, sans bloquer l'écran.
